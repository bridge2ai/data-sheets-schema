# Native shared receipt policy v1

This policy belongs to native_shared_generation_v1, renderer 26, generic_v10,
and receipt instrument 4. Its external registration binds these exact bytes.
The sole runtime declaration supplies the asserted output ceiling. Selection
bounds supply byte limits. Neither selects a default model, budget or floor.

## Prompt body

Preserve the validated original full, original receipt and complete original
source identities. The fixed receipt helper identifies every uncovered
receiptable leaf against the captured schema. If there are none, record the
verified zero-work result without a model answer. Otherwise admit exactly one
complete receipt request and retain the first raw answer before parsing it.
Never regenerate full, retry an answer or reopen a consumed stage.

Return exactly one YAML mapping containing only a rereceipt list. For EVERY
listed path return exactly one item: {path: ..., receipt: {chunk: cNNN,
snippet: ...}} with a verbatim supporting passage from that exact source chunk,
OR {path: ..., unsupported: true, reason: ...}. Never add, repeat, rename or omit
paths. Never edit a record or receipt yourself. Use only uniquely listed chunks
with status extracted, nothing_relevant or redundant_with, not duplicate_of.
Inspect the containing passage and its qualifications; quotation identity does
not establish scientific support. Preserve verified negative-status reversals.

The helper preserves verified partial additions, every rejected or unanswered
item, and every unsupported candidate with its reason, origin and pinned input
identity. It retains the fixed original before/after denominator and effective
receipt lineage. Unsupported candidates are carried into the complete typed
audit; they do not authorize automatic deletion. Helpers refuse drift and
duplicate publication instead of merging the same addition twice.

The registered production floor is the exact integer fraction with_receipt /
receiptable on the final record, using the unchanged receipt counters. A zero
denominator cannot become a fabricated 100 percent. A pending floor remains a
diagnostic pilot and cannot satisfy strict completion. Receipt additions and
coverage do not certify truth, resolve applicability or replace origin/padding
diagnostics, independent audit or the final evidence checks.
