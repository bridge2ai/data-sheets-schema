## Native shared generation stages v1

Use the captured generation context, profile vocabulary and declared sources in
every applicable stage. The context declares the scope and source policy; it is
not evidence that a claim is true or scientifically applicable. The supplied
schema specifies structure, never dataset facts. Do not consult earlier D4D
records. Supported role relationships require evidence for the containing role,
not just for a person's or organization's name.

Generate the full record and original receipt from the complete declared bundle.
Use the exact registered validation and seal commands before advancing. Original
full, original receipt and original core become immutable when sealed. Neither
later reconciliation nor receipt additions may rewrite those originals.

Run the registered stage advance command exactly. The helper publishes the
current request only after checking its predecessor and the observed history.
Read that entire current request with a successful Read before writing one raw
answer to its exact admitted response destination. Follow its complete policy,
inventory, owner context, schema and output format. Do not create requests,
journals, records, observations, seals, indexes, assemblies or completions; these
belong to the controller and its fixed helpers. A proposed request is not Write
permission. Future, stale, failed and already consumed responses are not writable.

The receipt stage admits at most one answer. A genuine zero-work result requires
no answer. After receipt checking, derive the core with the registered helper
from the sealed original full and effective receipt; preserve the distinct core
seal. Advance through every assigned worker, the complete omission inventory
and integration in order. Never skip a worker, shorten an inventory to fit a
limit or answer from a remembered request. Return only the requested raw answer;
the helper retains it and derives any internal response envelope itself.

A failed, malformed, interrupted or uncheckable response remains consumed. Stop
the attempt; no second answer, restart or extra generation is authorized by this
procedure. The caller's byte, inventory, history and evidence bounds apply to
the whole required content. The sole runtime declaration's output-token limit
is an asserted runtime ceiling, not a per-stage guarantee or a session budget.

After the full typed assembly is independently checked, reconcile using its
complete findings, receipt carry, omissions and source qualifications. Audit
annotations are review evidence, not automatic authority to delete supported
values or to add unsupported ones. Preserve source-supported content and account
for every requested correction and every unexplained loss. Re-derive the final
core from the final full; do not generate independent core facts. All final
schema, pair, receipt, evidence, removal and source-review checks remain required.

Check the final report draft with the registered source-attribution preflight.
Within the explicit execution draft-check allowance, correct only that unaccepted
report draft and preserve failed checks and correction history. A passing check
binds its exact report, full record and input bytes. Run the terminal evidence
check only after a current draft pass. A terminal failure is sticky. Finally run
the exact registered live recorder command after the complete required checks.

A stage completion certifies only the reconstructed receipt and typed assembly.
It does not certify native session success, model attention, scientific support,
human labels, applicability, an empirical receipt floor or launch authorization.
