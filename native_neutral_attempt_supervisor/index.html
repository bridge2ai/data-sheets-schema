    Neutral native attempt supervision

    data_sheets_schema.native_attempt_supervisor coordinates one ordinary local Python fixture, through the unchanged native controller and its reviewed attribution callbacks. It has no native executable, authentication, provider client, arbitrary argv CLI, paid budget or production execution mode.

    The programmatic sequence is registration(...), supervise(exact_bytes), and read_final(exact_bytes). Registration requires a verified composition, a JSON fixture with exactly four text artifacts (full, receipt, audit, report), an explicit attempt ID, new disjoint attempt/evidence/output directories, a positive local deadline of at most 3,600 seconds, and all synthetic runtime, model, auxiliary-model, effort, limits, usage and cost declarations. Individual registration/fixture files are limited to 8 MiB. The selected helper interpreter and resource paths must exactly match this installation's captured toolchain. The request must declare provider="neutral fixture (no provider)". Its native RunSpec runtime selects the historical instruction grammar; the actual child runtime is separately identified as neutral-local-v1. This is not a report that Claude Code or a model executed the fixture.

    Use an explicit standalone source manifest and the manifest-rooted corpus layout, with out_dir=None. The real receipt CLI selects paths by that manifest, method, label and project. A replayed RunSpec's ordinary path properties are not substituted for its captured agentic_artifact_paths. The supervisor's adapters use those exact registered artifact identities throughout.

    The fixed recipe reads the selected sources, writes the neutral full record and coverage receipt, runs the real strict receipt checker and deterministic core derivation, freezes both originals exclusively, runs original source inventory and audit evidence, completes the final derivation, runs final inventory, writes the reconciliation report, runs the draft and final evidence checkers, and runs the one exact recorder. Helper commands come from the verified composition. Callers cannot inject a shell command or replace the recipe's executable. The final recipe gate requires the exact ordered calls and inputs, one settled result per call, explicit integer-zero exits and matching result text, and source-read content equal to the captured bytes. No pending handler state or controller failure can be hidden by a zero child return code.

    An attempt directory's exclusive reservation consumes that canonical attempt identity. Its containing directory is synced immediately after reservation, before registration/started writes. The new evidence directory's parent is also synced before dispatch. A failed barrier prevents dispatch and retains the reservation and any partial evidence; it is never treated as successful durable consumption. A failed or partial start never automatically retries or resumes. The fsynced started record precedes the sole controller dispatch. Both callbacks and phase_spec are supplied to the frozen controller, preserving phase order, terminal stops and bounded shutdown. The environment is explicitly constructed without inherited provider credentials.

    After shutdown, one captured byte basis feeds the saved attribution reader, phase replay, schema, pair, receipt, evidence, transcript observation, terminal, synthetic accounting, effort and limit checks. Path-based schema/observation checks read exclusive retained byte-identical projections. Pair checks use the same captured merged schemas with the fresh-attempt schema_moved=False basis. Receipt source binding executes the unchanged frozen binding function using a private sealed-path adapter. The pure receipt checker retains canonical chunk validation, exact recorded source hashes/rules/counts, authoritative phase-1 snapshot selection, captured schema aliases, receipt-policy selection, and the existing strict floors. No historical recovery or current-schema fallback can stand in for this new attempt's registered bytes. No original file is repaired.

    The additive dependency identity covers the old twelve-module closure plus the two direct helper modules at their explicitly pinned released hashes, exact package/schema bytes, source HEAD and Python identity. Imported module origins are checked as well as bytes; loader path and bare-module state are restored. The old controller manifest, launchers, defaults and registrations are unchanged. No old launcher main or auth helper is used.

    Every required check has a named boolean outcome. Failed or unavailable checks cannot disappear from completion. Safely readable stopped evidence still gets independent checks, and the first controller stop remains alongside later errors. Raw transcript, control log, stderr, artifacts, failed staging files, captured projections and replay report are retained. final.json is not a published result without its separately fsynced, hash-bound published.json. Readback refuses changed captured bytes, symlink/inode/link/mtime metadata, generated replay-report bytes, aliases and inconsistent gate membership. A failed marker-directory fsync or staging unlink retains two links to the marker; readback requires a single-link regular marker and refuses that state. Publication errors do not remove evidence or authorize redispatch.

    The public fixture test provides a complete positive using real receipt, derivation, schema, pair and evidence helpers; its four values are exact quotes from an explicitly synthetic local source. The initialization, effort and usage events are intentionally fabricated neutral protocol data. Only engineering_completion may pass. generation_acceptance, native_permission_proof, provider_metering and launch_authorization always remain not_assessed. Local hashes establish consistency, not authenticated model execution or scientific support.

    This completes the offline coordination slice tracked by #4325. Real runtime registration/adoption, permission evidence, scientific condition approval, explicit route/effort/context/budget selections and launch authorization remain under #2427 and #3336. An engineering result cannot satisfy those obligations.
