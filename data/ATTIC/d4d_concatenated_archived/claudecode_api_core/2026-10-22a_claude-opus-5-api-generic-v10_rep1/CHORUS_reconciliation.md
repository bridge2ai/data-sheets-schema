# Reconciliation report — CHoRUS dataset

## Scope and referent

The record describes the CHoRUS dataset at `https://chorus4ai.org/`, as declared. That choice is unchanged by this reconciliation: no source passage in the bundle was moved into the referent's own slots from a passage about another dataset, and no related dataset was declared or added.

## What the audit found

The computed audit counts give **12 findings: 6 medium, 6 low** (no high). They divide into one correction and eleven omission findings:

- **One correction** (medium, `source_caveats`): the original full record asserted that the two admission counts "come from two sources with different observation times". Only the webinar bullet carries a date ("As of August 2025"); the project website's Current Released Dataset snapshot states none, so the documents do not establish differing observation times. The compatibility half of the clause was found supported.
- **Eleven omission findings** proposing source-stated material absent from every field of the record, across `description` (two findings), `ethical_reviews`, `purposes`, `notes`, `conforms_to`, `conforms_to_standard`, `existing_uses`, `external_resources`, `preprocessing_strategies` and `extension_mechanism`. Each finding stressed that the added text must keep the source's planned, ongoing, instruction or availability status.

No finding carried a `remove_relationship` action, so no relationship was removed in this reconciliation and no identifier was altered. The `creators[0]` entry — Eric S. Rosenthal, with its own caveat that NIH RePORTER designates the role for the project rather than for the dataset artifact — is byte-identical before and after, as are its nested `principal_investigator.id`, `principal_investigator.name` and `affiliations[0].name`.

## Changes to the full record

**Corrected (1 finding).**

- `source_caveats`: the opening clause now reads that the counts "come from two sources and are compatible rather than contradictory", with the website "stating no observation date" and the conclusion that "because the website gives no date, the documents do not establish when either count was observed or in what order". The original phrase "with different observation times" is gone. Two further sentences were added to the same value: the PhysioNet cell is named among the per-row cells that cannot be attributed to a data type, and a sentence explains what the new `OTHER` enumeration entry stands for.

**Added or expanded (11 findings).**

- `conforms_to` (changed): a sentence recording the dataset table's published-metadata-schema cell reading "Yes (PhysioNet schema extended)", with the explicit statement that the owning data type cannot be determined from the interleaved extraction. No row/column mapping was asserted.
- `conforms_to_standard[3]` (added): `OTHER`, the registered value for a source-named standard the enumeration does not list. The specific standards remain in `conforms_to` in the sources' own words; the caveat names them.
- `purposes[3].response` (added): the abstract's enumerated aim of cultivating expertise in the lay and scientific community to improve AI literacy and utilization through multimodal educational approaches, carried with a leading "Planned." marker matching the record's convention. (The source spells this "AI literacy nd utilization"; the record restates it.)
- `ethical_reviews[0].review_details` (added): the community-facing ethics focus groups the abstract lists among activities the project will perform, marked planned, with an explicit statement that no completed focus group is reported.
- `preprocessing_strategies[3].preprocessing_details` (added): the overview's future-tense statement that unified standards will harmonize multi-modal EHR, waveform, imaging and text data, marked planned.
- `intended_uses[2]` and `intended_uses[3]` (added): the webinar's future-tense statement that trainees will leverage the data and tools to create practical use cases and data-driven research during hands-on training on the Bridge2AI AI/ML for Clinical Care Network, and the website's statement of learning opportunities using the CHoRUS dataset. The audit filed these under `existing_uses`; because both are future-tense or availability statements, they were placed in `intended_uses`, whose `usage_notes` record that framing.
- `external_resources[2]` through `external_resources[5]` (added): the Bridge2AI AI/ML for Clinical Care Collaborative Cloud; the chorus-developer web guide and package status page; chorus-container-apps; and UF-Geocoding. Each entry records the scope limit the audit required — no distribution claim for the Collaborative Cloud, no processing-tool version or maintainer role from the package page, and no application of the Azure applications or the geocoding code to this dataset.
- `extension_mechanism.extension_details` (changed): three further workflow steps were appended — the site status-tracking request and its Google Form/GoogleScript mechanism, CHoRUSReports, and chorus-extract-upload — with the request to sites labelled an instruction and the repository descriptions carrying no version or release-specific application.
- `description` (changed): two blocks added — the abstract's three pillars with its target of an AI-ready data set from more than 100,000 critically ill patients and the contextual-factors commitment, both marked as planned project work; and the website's ongoing standardization practices, tool creation for the cloud enclave and legal/regulatory analysis, plus the overview's future-tense privacy/bias/SDoH sentence. (The source spells one pillar "Data Acquistion" and writes "will addresses"; the record normalizes both.) No variable was created from the contextual-factors clause.
- `notes` (changed): the abstract's prospective collaboration sentence, with an explicit statement that it assigns no role for this dataset to any named body, and the webinar's AIM-AHEAD/Bridge2AI training-collaboration sentence.
