# Canary sizing method — 2026-09-16 (v10q)

The local cost proposal prices the complete new audit/report payloads before
any provider call. The public [sizing view](sizing.public.json) retains volumes,
ceilings, assumptions and the exact private calculation digest. Prices,
proposed financial terms and historical usage/accounting remain local.

1. Read unchanged v10o original/final full and derived-core bytes solely as
   volume references. Enumerate the exact renderer-12 source-review inventories.
   Every prior original remains hash-checked and unchanged.
2. Build a sizing specimen with one claim per scalar, a 160-character source
   quotation and a 120-character reason. These placeholders are not source
   judgments, valid scientific evidence or generation inputs. Real values can
   contain several atomic claims. Record compact and formatted JSON sizes.
3. Build each current API phase with its complete bundle, prompts and schema.
   Include measured original/final artifacts and the sized new audit when the
   phase carries them. Kids First uses its actual source input with CHORUS's
   carry-volume specimen; no real Kids First output size has been observed.
4. Compute input/output sensitivities at three, four and five characters per
   token, with 8k and 16k assumed review reasoning, 4k audit findings and 6k
   report prose. Hold historical full/reconcile output totals fixed solely for
   this sensitivity. These ratios are not actual token counts or bounds. Any
   output scenario exceeding its ceiling cannot represent a completed attempt.
5. Separately apply the transport reservation formula to each input scenario:
   `(ceil(input_tokens * 1.2) + 1024) * max(input_rate, cache_write_rate) +
   output_ceiling * output_rate`. Sum four main phases as a stress scenario;
   it is neither a cost forecast nor a reservation. The proposed whole-attempt
   cap can be below that sum because completed calls settle before the next
   reservation. If actual settled spend plus the next reservation exceeds the
   cap, the attempt stops, even when an illustrative cost scenario fits.

Use the freshly observed CBORG rates, with no assumed cache hits for these
sizing calculations. Conditional receipt readdressing, usable-response retries,
ordinary report correction and legitimate shape repairs are excluded from the
four-main-call scenarios and consume the same attempt cap. Failed/unusable v3
source reviews stop without replacement calls. No smaller output limit, source
trimming or lower review coverage is used to force affordability.

Native retains its distinct pinned runtime limits. API phase totals do not
forecast native costs: tool turns, rereads, auxiliary requests, compaction and
response lengths are unmeasured. Every native model call passes the same live
counting and serial budget admission. The native attempt caps are ceilings,
not empirical estimates or promises of completion. Source acceptance requires
inspection of actual checker tool results and stop behavior.

There were no remote token-count or generation calls in preparation. The
registered initial requests have additional one-token-per-UTF-8-byte sizing
scenarios, explicitly not verified tokenizer bounds. Actual token counting
belongs to an authorized attempt and happens immediately before each reserved
generation call. Current prices, source identities and settled accounting must
be rechecked before a launch receipt. The proposed combined-ceiling amendment
is still pending; neither this document nor a merged registration approves it.

**v10q.** The API sizing above is carried unchanged: the sources, prompts,
digests and phase allowances are v10p's, and the only new bytes an API
request carries are none (the digest did not move with the schema
release). The native arm runs first under this registration and remains
unmeasured: no native attempt has completed under any v10 condition, so its
cap is a ceiling with no empirical basis yet, and the first accepted native
canary is the first sizing observation for that arm.
