# Native eligibility source audit

Today the source supports only a conditional end-state proxy like rule A, not the ratified plan eligibility rule. A saved current derive_final_core check can identify an unchanged, successfully validated derivation when the final/live phase report and current file survive. It misses post-derivation validation failures, previous completed records invalidated by later writes, and attempts without a saved report. Rule B needs new durable event-bound full-byte retention plus an eligibility reader independent of successful finalization. A SHA-256 alone is insufficient after overwrite. No code was run or edited for this audit.

One correction to the review: a failed attempt is not categorically unreadable. read_final accepts a properly published failed runtime result when its retained identities/gates validate. What is absent is a reader that recovers/selects an eligible completed full-record snapshot from rejected, stopped or incompletely published attempts.

## Rule A and its reader

Rule A would require an explicitly chosen authoritative report location, a source/registration/attempt match, current_checks, the retained full path and a newly computed SHA-256, plus the prior captured-file pin where available. Do not require phase.passed or runtime_gates_passed: those would discard unrelated late failures. Conversely, accepting a copied current_checks flag alone would not prove byte/event identity. Live and replay reports are not interchangeable by default: replay can be unavailable on precisely the stopped cases of interest.

A subsequent full-write attempt increments the full epoch immediately, invalidating the previous derivation even if the write is interrupted. A core-only mutation can also invalidate it. If a rewrite succeeds without a fresh derivation, A excludes the record; if the file is changed outside observed effects and someone merely hashes the new bytes at review, A risks selecting bytes the check never covered. Neither behavior implements retention of the prior completed snapshot. A validation-failing derivation can leave a completed full and core but no passed derive_final_core. No saved phase report means A is unavailable, not evidence that reconciliation did not occur.

A published-failure read_final can validate retained failure evidence, but it does not implement A. There is no defined selector combining those nested reports and current full bytes for analysis. Raw transcript reconstruction may support a forensic investigation; it is not an existing validated recovery rule and cannot guarantee overwritten bytes survive.

## Rule B cost and a better completion boundary

Use immutable copies or a content-addressed byte store, not hashes alone. A new dedicated eligibility journal under the registered attempt/evidence area should bind each snapshot to registration/attempt, selected full path, byte length, SHA-256, event position/raw-event digest, tool identity, predecessor and completion kind. Write/fsync the complete bounded snapshot first, then durably publish its index record; publish neither a partial snapshot nor a false completion. Preserve every completed predecessor and never require successful schema validation or final.json for readback. Interrupted index publication must have a specified recovery policy, with no promotion of uncommitted entries.

Simply adding a snapshot on exit-zero derive_final_core is insufficient. The helper writes/prints before validation, and some completed but shape-invalid full records can fail before core derivation succeeds. Prefer an explicit reconciliation-completed boundary after the final full write and before validators, with subsequent completed full repairs likewise snapshotting their bytes. If NP1 deliberately chooses completed derivation instead, it must distinguish derivation completion from validation and acknowledge any narrower eligibility population; the amendment must settle that semantic boundary before implementation.

A controller-side hook near native_shared_controller_orchestration.observe/phase actions can retain bytes at a delivered event. To survive death after helper completion but before the controller receives the result, a durable helper-side receipt/snapshot or an equivalent atomic completion protocol is needed; buffering and signal windows must be tested. This is a cross-layer retention protocol, not a new field on current_checks.

Expected implementation surface: a bounded immutable snapshot/journal producer and reader; explicit completion receipt in the helper/controller; phase/event joins and capture/replay integration; final reporting of snapshot references without using final success as eligibility. Tests should cover schema/derivation validation failure, duplicate-key bytes, repeated repair, interrupted full rewrite, interruption between snapshot/index/result delivery, late gate rejection, failed or absent publication, changed bytes/hashes/events, gaps/duplicates, and current-vs-original records. Existing phase, observations, controller, capture, saved-results, execution, derive CLI and crash-persistence cohorts need extension. No numeric effort estimate is supported by this read-only audit.

Pins: changed source files and any new package module alter package_sources, dependency/source identities, permission production-source closure, registration and downstream review/word/probe bindings; helper argv changes additionally move command-policy/render and scanner derivations. Native controller manifests that pin an edited external helper would require separate review. No protected file must be edited merely to add a native retention module, but RunSpec-boundary discovery and scanner closure must be audited before choosing the exact design. No pin was updated here.

Rule B needs a dedicated stopped-attempt reader: exact registration, immutable snapshot and journal entry, event/receipt binding, complete prior index chain, and byte/hash verification independent of final publication. It must return eligible bytes and selection provenance, or missing/unverifiable reasons, without promoting a failed attempt to accepted. That reader does not exist today.
