# A17 / R7b-F1 admission ceiling repair

2026-10-27. Refs #5211, #5155. Base:
`2172bdd591f64a1a9f0fdd3220a8ff8ce826a6b4`. Work is confined to fresh branch
`codex/a17-r7b-fix-20261027`; the implementer's original branch is preserved.

Previously, reducing CHORUS's context or per-call input ceiling left
`profile_covered` true. Supplying the tracked sizing record exposed a worker
that would not fit; omitting that record skipped sizing and prepared the same
registration. The four prior causal review cases are now in the ordinary
builder test module with their assertions unchanged.

Profile coverage requires unchanged partition bounds and output caps, sufficient
aggregate input, and context/input/request-byte ceilings no smaller than those
used for calibration. A supplied record can re-estimate tighter context or
input-token limits using the existing instrument. Positive coverage retains
that route when expected worker, omission and integration demand fits; an
oversized worst-case integration still produces the existing warning.

The current instrument counts rendered text components, a receipt-carry
allowance and calibrated response contributions. It does not measure the whole
canonical provider request, including JSON escaping/framing. Therefore both
preparation and saved-sizing validation refuse `max_request_bytes` below the
retained 32,000,000-byte calibration ceiling, even with a sizing record. This is
an explicit conservative limitation, not a new claim that every future request
fits that ceiling. Supporting a smaller cap requires complete wire-byte
calibration; runtime admission remains authoritative. No approximate-byte
instrument or new response-size estimate was introduced.

Saved sizing records continue to bind the registration SHA. Their token
admission is now checked against `min(max_input_tokens_per_call,
context_limit_tokens - stage_output_tokens)` from the current registration;
stale saved `admissible_input_tokens` cannot grant additional room. The sidecar
is not external authentication, and this check is not a scientific judgment.

Additional regressions cover each ceiling at/either side of calibration,
omitted and explicit records under a smaller byte cap, a fitting explicit
re-sizing under tighter token limits, and stale sidecar room after changing
context, input or byte ceilings. Original adequate-calibration positive cases
remain in place. No source bundle, generated record, old sidecar, schema,
prompt, runtime controller or protected module is changed.

Validation is pending at source-review time. The saved helper

will run the complete requested `tests/test_build_api_registrations.py` and the

bound to tracked source hashes, exact test-module scope, duplicate-identity
refusal, retained logs/JUnit and source comparison after execution. Recorded
dependency versions do not attest installed dependency bytes. No provider,
