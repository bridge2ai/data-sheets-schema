**CBORG interrupted-stream investigation — September 16, 2026**

The repository rejects incomplete responses, but the provider/proxy cause of [#1849](https://github.com/bridge2ai/data-sheets-schema/issues/1849) remains unresolved. This change addresses the separate local evidence gap in [#1877](https://github.com/bridge2ai/data-sheets-schema/issues/1877). It does not authorize a retry, change a canary's financial controls, or establish scientific acceptance of a stopped run.

**What the preserved attempts establish.** The two interrupted full-generation attempts and the later interrupted source audit all raised `httpx.RemoteProtocolError` for an incomplete chunked response. The client recorded approximately 394, 452 and 393 seconds respectively, no output text, and partial usage. The provider records describe empty successes; the most recent record exposes no error/routing explanation and says zero retries were attempted. Its HTTP status and usage snapshot are not terminal-completion evidence. The application deadline was 3,600 seconds. The reviewed Anthropic 0.72.0/httpx 0.28.1 client has a 600-second default read timeout; these failures are not recorded as `ReadTimeout` or watchdog expiry.

These facts do not identify which network component closed the connection. Similar durations do not establish a fixed proxy timeout. The old snapshots discarded the observed event count and did not retain terminal-event history, so wire pings, the timing of individual SDK events and provider liveness cannot be reconstructed from them. Provider prompt-storage elisions are not evidence that the forwarded prompt was truncated. The explicit context-bypass header was requested; provider enforcement remains unverified.

All previously requested complete-charge confirmations have been resolved. The original stopped artifacts and pending accounting remain preserved beside their separate reconciliation. Unobserved final token usage remains unobserved; reconciliation does not turn these runs into accepted D4Ds. Private request identifiers, exact request bytes and billing details remain in local evidence, outside this public note.

**The local defect and correction.** `_call_with_retry` previously counted events in its worker but passed `events=None` to the failure recorder after a transport exception. It now freezes a bounded trace for each failed attempt, including failures signaled by a nonretryable provider SSE error after the stream opens. The trace is stored in the existing output snapshot, abandoned-attempt journal and usage row, so it survives a failed process and later record merge.

| Evidence | Meaning and limit |
|---|---|
| Event count/type counts; last 16 event types | Events delivered by the SDK, not wire SSE frames. Unknown types share one bounded bucket. |
| First/last event and response-header observation times | Elapsed monotonic seconds from call start. These are client observation times, not server timestamps or a network-idle measurement. |
| Message-start/delta/stop flags and declared stop reason | Distinguish a missing terminal event from a framed response without a stop reason. A failure after a stop event is still a failure. |
| Content-block type counts | Identify text, thinking or tool block starts without retaining their payloads. |
| HTTP status and allowlisted correlation headers | Join local evidence to provider records. Only bounded identifier-shaped `request-id`, `x-request-id`, `x-litellm-call-id` and `cf-ray` values are retained. HTTP 200 is not completion. |
| Exception class and declared provider error type | Preserve a stream error arriving after HTTP headers, including HTTP 200. Arbitrary error-body text is excluded from the new trace. |

Before iteration is available, event count and terminal flags remain null rather than asserting zero observed wire traffic. Trace collections are copied before recording, and each worker owns its trace; a late abandoned worker cannot update an earlier snapshot or another attempt. The new metadata does not contain prompt/output payloads, reasoning text, signatures, tool arguments or arbitrary headers. The pre-existing bounded output tail and partial-usage snapshot retain their existing behavior. Correlation identifiers are diagnostic data and should remain local when publishing redacted study outcomes.

The existing completeness guard, error classification, retry limits, SDK settings and budget controller remain in force. A framed response without a stop reason now has an accurate diagnostic outcome instead of claiming a missing stop event. The watchdog message says “giving up” when the configured final attempt has been reached. Registered canaries still disable both SDK and controller retries.

**Why this is not a wire trace.** Anthropic documents `message_start`, content blocks, `message_delta` and terminal `message_stop`, with possible ping/error events. The pinned SDK filters ping frames, raises on provider errors and emits synthetic text/thinking events. The implementation and tests therefore label the new data `sdk_events_not_wire_sse`; an absent observed ping cannot establish that no heartbeat crossed the network. See the [streaming protocol](https://platform.claude.com/docs/en/build-with-claude/streaming), [pinned raw SDK stream](https://github.com/anthropics/anthropic-sdk-python/blob/v0.72.0/src/anthropic/_streaming.py) and [pinned message stream](https://github.com/anthropics/anthropic-sdk-python/blob/v0.72.0/src/anthropic/lib/streaming/_messages.py).

The [CBORG usage guide](https://cborg.lbl.gov/api_faq/) recommends streaming for slow responses and documents a direct `api-local` path for clients on LBLnet. The failed attempts already streamed. That alternative endpoint is a possible diagnostic to discuss with CBORG, not evidence that Cloudflare caused these failures or an approved endpoint substitution. No endpoint, model, thinking allowance, effort or timeout was changed. The guide's retry advice does not override registered scientific/budget controls.
