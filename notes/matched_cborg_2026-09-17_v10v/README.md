## What changes

Native policy version 3 checks Bash commands before execution through a parent
`PreToolUse` callback, using the same job-specific classifier as the terminal
audit. It denies commands outside the registered grammar and preserves runtime
isolation. Missing, malformed or timed-out decisions stop the controller.
The policy and callback code are pinned; recorded decisions must match the
native calls and results. Blank commands remain non-disqualifying denials.

The system guidance, native control protocol and command policy change; both
arms receive new condition and output identities. Historical attempts keep
their original procedures and verdicts. These controls are not a filesystem
sandbox. File-tool paths, helper arguments, required checks and phase ordering
still need independent review. Lookup permission does not replace ordered
chunk reads or immediate receipt writes. The pinned Claude Code 2.1.272
binary passed 27 synthetic command cases with and without project settings,
plus three control-failure probes, with zero real provider requests.

The registration also fixes the standalone overlay preparer import path
(#2059). A clean-subprocess test failed before that correction and passes
after it; all 14 command-policy tests pass. The corrected preparer is pinned
by this registration and is reviewed with it.

Source bundles, chunk maps, profiles, schema 3.0.0, renderer 12, evidence v3,
source-review v1 and evaluation definitions retain their identities. Both
arms use CBORG `claude-opus-5` on the registered route. API requests retain
adaptive thinking with no explicit effort override; native retains default
effort, its observed 200k context and 64k output ceiling per call, and a
10,800-second attempt deadline. These limits do not establish equal realized
effort, deterministic generation or completion cost.

## Acceptance and sequence

1. Run one CHORUS native canary after its gates pass. Preserve the complete
   request/tool history, full record, derived core, receipts, provenance,
   unchanged original snapshots, structured audit and reconciliation report.
2. Inspect the original and final claims against the exact credited documents,
   with each clause, governing context, qualifier and role checked separately.
   Receipt coverage and declared judgments alone do not establish entailment.
   Check schemas, deterministic core derivation, pair consistency, provenance,
   grounding, source-review inventories, evidence assertions and report claims.
3. Verify observed receipt writes before subsequent chunk reads, the strict
   receipt gate before core derivation, and printed original-freeze hashes
   before reconciliation. Reject continuation after failed evidence/source
   checks. Require clean command-history and control-evidence checks, then inspect actual targets
   and helper arguments. List every denial; a denied prescribed or unclassifiable
   call disqualifies. Every stop needs its named cause and ledger entry.
4. After unchanged-canary acceptance, run Kids First native under the neutral
   profile, then the two API canaries, accepting each before the next. A failed
   or stopped canary stops expansion. API transport #1849 remains unresolved;
   native execution does not establish an API transport repair.
5. Register evaluation canaries on accepted exact inputs, then use measured
   costs and reviewed outputs for the production decision. #1801/#1815/#1816/
   #1782 remain open until independent scientific acceptance.
