# Generation source-scope correction — 2026-09-14

The v10e CHORUS API canary completed with valid full/core records and passed
mechanical checks, but failed independent source review. Its audit treated
an excerpt from an activity governed by a future commitment as an attested
applied method. The final records also asserted a planned data component as
present and called compatible count observations contradictory. The original
condition and all 38 files remain preserved in the v10e rejection record.
Related issues: #1782 and #1792.

The correction applies to every dataset and both generation runtimes:

1. Read the governing clause or heading across dependent clauses and list
   items, including any explicit local change of scope. Matching a short
   excerpt does not establish the status that its enclosing passage gives it.
2. Require evidence of actual presence or application for such assertions.
   A documented plan also does not establish current absence. Keep supported
   plans qualified in fields that permit them.
3. Establish numerical and contextual incompatibility before invoking source
   priority. Exact values, approximations, ranges and bounds retain their
   meaning; differing units or document dates alone establish no conflict.
4. Apply the same source check to an audit recommendation before accepting
   it as a repair. A recommendation cannot make a fragment stronger evidence.

The API system message carries these rules into every generation phase; its
audit and reconciliation instructions explicitly apply them. Native full/core
and standalone generation use the shared uniform rules and updated playbook
checks. Historical condition-prompt files, source bytes, schemas, profiles,
scoring instruments and effort settings are unchanged. There is no new model
phase, automatic retry or post-hoc edit of a measured scientific record.

Validation uses the existing runner, playbook-reach and selected-input tests,
plus offline inspection of rendered requests and native instructions. These
checks establish instruction delivery and regression safety, not model
compliance. Independent review and a freshly registered canary remain
necessary before claiming the source-scope issue resolved.

Both API and agentic generation arms, full/core variants, five Bridge2AI
datasets and the external Kids First bundle remain planned. The evaluation
sequence retains deterministic presence checks, both semantic rubrics and
repeat ratings, direct API quality, field-agent evaluations, applicable
grounding/fitness/subtype judgments, receipts/reports and separate historical
adjudication. All new scientific inputs need their exact source/instrument
registration; the failed v10e attempt is not an accepted evaluator input.
