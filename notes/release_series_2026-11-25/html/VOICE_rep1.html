Motivation

For what purpose was the dataset created?

Response
To provide an ethically sourced flagship dataset that enables future research in artificial intelligence and supports critical insights into the use of voice as a biomarker of health, with which clinically applicable AI/ML models can be developed, benchmarked or validated.
To facilitate the use of voice as a non-invasive, cost-effective biomarker for the screening, diagnosis and monitoring of a wide range of health conditions.

How was the data associated with each instance acquired?

doi:10.13026/37yb-1t42
Bridge2AI-Voice
Bridge2AI-Voice: An ethically-sourced, diverse voice dataset linked to health information
A collection of data derived from voice recordings with corresponding clinical information, published on PhysioNet as the adult dataset of the Voice project. Version 3.1.0 contains data for 833 participants collected across five sites in North America; the project documentation gives the countries of collection as the USA and Canada. Participants were selected based on known conditions which manifest within the voice waveform, including voice disorders, neurological disorders, mood disorders and respiratory disorders. The dataset contains derived audio data features, phenotypic information acquired during data collection (demographic, clinical and validated questionnaire data), and metadata related to the specific audio task and recording. The release contains data considered low risk, including derivations such as spectrograms, but not the original voice recordings.

Previous studies of machine learning-based voice diagnosis produced promising results, but their sample sizes were too small or they lacked the key metadata needed to train robust, clinically useful models.

Bias Description
The public data releases do not contain an equal distribution of the disease categories; the dataset has skews based on disorder category, site and other demographic factors.
Groups that have less trust in the medical system or in AI, or that are less proximal to the collection sites, would have been less likely to be recruited.
Participants were screened for different disorders based on site, so their data were also collected with different devices.
Limitation Description
Distinct iPad devices were used at each site.
The data were recorded with a head-mounted headset with a microphone that could be at slightly different distances.
The clinical diagnosis, depending on the disorder, was performed by one clinician or based on an EHR record or prescription.
Noise artifacts are a possible confounding factor.
Variations in diagnostic practices are a possible confounding factor.
Inaccurate questionnaire responses are a possible confounding factor.
Underreporting is a possible confounding factor.
Changes in diagnostic criteria or practices could be a source of distribution shift over time.

Deidentification Details
State and province were removed and the country of data collection was retained. Spectrograms and similar features were excluded if the audio contained free speech, while static and other features which do not encode the sensitive information were retained. All raw voice data were removed from the release. The project documentation states that identifiable information (under HIPAA and the Common Rule), as well as data considered sensitive, have been removed, that dates are rebased or replaced by integers, that narrative text fields are removed and that K-anonymization (k>=2) is not achieved. For version 3.0.0 the documentation states that raw audio transcripts were reviewed and any audio recordings that contained potentially identifying information and external voices were removed from the release.

Audio standardization
Raw audio was preprocessed by converting to monaural and resampling to 16 kHz with a Butterworth anti-aliasing filter applied.
Feature extraction
From the standardized audio, derived data were extracted. Spectrograms were computed using the short-time Fast Fourier Transform (FFT) with a 25ms window size, 10ms hop length and a 400-point FFT, and were further downsampled by a factor of two in the time domain after derivation. 60 Mel-frequency cepstral coefficients (MFCCs) were extracted using the spectrograms. Mel spectrograms were computed with the same parameters and 60 Mels. Articulatory features (kinematic traces of vocal tract articulators and source features, and measures of loudness, periodicity and pitch) were generated with the Speech Articulatory Coding (sparc) package at 50Hz. Acoustic features were extracted using OpenSMILE. Phonetic and prosodic features were computed using Parselmouth and Praat. Phonetic posteriorgrams at 100Hz were generated via the ppgs package. The code used to process the raw audio into these features and to merge the source data into the phenotype files is the open source b2aiprep library; this release was generated with b2aiprep v3.0.0. The project documentation states that all processing is performed using the b2aiprep and SenseLab toolkits.

Version Details
PhysioNet lists versions 1.1 (January 17, 2025), 2.0.0 (April 16, 2025), 2.0.1 (August 18, 2025), 3.0.0 (December 16, 2025) and 3.1.0 (May 1, 2026). The files for version 1.1 are no longer available on PhysioNet. The project documentation's datasheet states that, by default, older versions of the dataset will continue to be supported, hosted and made available to researchers and that each version has a unique DOI.
