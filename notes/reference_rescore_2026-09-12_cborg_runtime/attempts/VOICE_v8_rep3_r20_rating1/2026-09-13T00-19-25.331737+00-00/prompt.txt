preprocessing_strategies:
- preprocessing_details: >-
    Raw audio was preprocessed by converting to monaural and resampling to 16 kHz with a
    Butterworth anti-aliasing filter applied.
- preprocessing_details: >-
    Spectrograms were computed from the standardized audio using the short-time Fast
    Fourier Transform with a 25 ms window size, 10 ms hop length and a 400-point FFT, and
    were further downsampled by a factor of two in the time domain after derivation.
    Sixty Mel-frequency cepstral coefficients and a 60-bin Mel spectrogram were derived
    with the same parameters.
- preprocessing_details: >-
    Articulatory features were generated using the Speech Articulatory Coding package,
    producing kinematic traces of vocal tract articulators and source features together
    with loudness, periodicity and pitch measures, all gathered at 50 Hz. Phonetic
    posteriorgrams giving a time-varying categorical distribution over acoustic units of
    speech were generated at 100 Hz.
- preprocessing_details: >-
    Acoustic features were extracted using openSMILE, capturing temporal dynamics and
    acoustic characteristics, and phonetic and prosodic features were computed using
    Parselmouth and Praat, providing measures of fundamental frequency, formants and
    voice quality.
- preprocessing_details: >-
    Transcriptions were generated using the OpenAI Whisper Large model. Transcripts of
    free speech audio were removed before release.

cleaning_strategies:
- cleaning_details: >-
    No pre-processing was performed for the purpose of cleaning the data, and no
    instances were excluded at the time of preprocessing. Quality control instead takes
    the form of an audit protocol run over the release: generating missingness tables,
    checking distributions and outliers, checking categorical responses against the
    schema, and running quality control metrics on audio tasks, including the amount of
    silence, the duration, and for speech tasks a comparison of the produced speech
    against the intended passage. Processing is performed with the b2aiprep and SenseLab
    toolkits. Version 3.1.0 adds a file of per-recording audio quality metrics.

  Referent: this record describes the adult Bridge2AI-Voice dataset at version 3.1.0 as

  audio distribution, which is the source this release derives from rather than part of
  it. Statements drawn from the project documentation and the IRB protocol that describe
  planned or future collection, other versions, or the pediatric cohort are marked as
  such where used.
  Brain Imaging Data Structure conformance is stated in the project documentation for the
  audio-plus-questionnaire distribution organized under a b2ai-voice-audio root, not for
  the PhysioNet featurized release described here, which is organized into features,
  metadata and phenotype folders; the BIDS fact is therefore recorded against the raw
  audio collection under related_datasets and no conforms_to value is asserted for this
  release.
  Remote data collection through the Bridge2AI Voice Web app and iOS app is approved in
  the IRB protocol but the project documentation states that remote data collection did
  not occur for the released data, and the PhysioNet methods describe tablet-based
  in-clinic collection only; it is therefore not recorded as a collection mechanism for
  this release.
  Target size: the project documentation states an anticipated enrollment of 10,000 by
  2027 and describes a flagship dataset of 10,000 voices, while the IRB protocol, at the
  same source rank, states a sample size of 30,000 participants, and the audiomics white
  paper states a primary deliverable of a publicly available database of 30,000 human
  voices. The two tier-2 sources cannot be separated by rank, so neither figure is
  recorded as dataset content; both are goals rather than realized collection, against
  833 participants actually released.
  Recording counts: the project documentation states that version 3.0 contains
  approximately 61,937 voice-derived recordings, while the PhysioNet version 3.1.0 release
  reports per-feature record counts ranging from 28,640 to 32,522 and no single recording
  total. These figures are not directly comparable and no reconciliation is attempted here.
  Name spellings differ between sources: the project documentation writes "Jennifer Sui"
  and "Frank Rudzizc" where the PhysioNet author lists write "Jennifer Siu" and "Frank
  Rudzicz"; the PhysioNet forms are preferred as the higher-ranked source.

  by the source capture; the DACO address recorded here is taken from the PhysioNet news
  items, which state it in full.

  The publisher value records PhysioNet, which the bundle names as the hosting platform
  and as the journal field of the release citation; the bundle makes no explicit publisher
  statement.
  No data protection impact assessment is recorded: the project documentation states that
  no analysis of the potential impact of the dataset and its use on data subjects has been
