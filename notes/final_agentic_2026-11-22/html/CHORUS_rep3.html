Collection Process

How was the data associated with each instance acquired?

CHoRUS
CHoRUS Dataset
https://chorus4ai.org/
CHoRUS (Patient-Focused Collaborative Hospital Repository Uniting Standards) is the dataset of the CHoRUS project, one data generation project of four in the National Institute of Health (NIH) funded Bridge2AI consortium. The CHoRUS project is the collection of multi-modal data across 14 different hospitals; the GitHub organization overview (captured 2025-11-14) states that the collaboration spans 20 academic centers, of which 14 will contribute as data acquisition centers. The project website reports a current released dataset of 50,000 patient admissions from ICU, PICU, and NICU, 1.6 billion rows of EHR OMOP data, 7,642 admissions with radiology data, and 23 Tb of waveform data, and describes an anticipated final dataset of 100,000 patient admissions, 9 different data modalities, and 14 data contributing hospitals, with 60+ CHoRUS consortium members across 20 different institutions. An AIM-AHEAD informational webinar (September 2025) states that, as of August 2025, the dataset covers 14 different hospitals with over 45K unique admissions; that OMOP and telemetry data are in the enclave, except that clinical notes are stored locally except tokens; that imaging currently has 1000 images available; and that EEG extraction is in process. The team creates tools to support the cloud enclave. The NIH RePORTER abstract states the project's plans: to acquire an AI-ready data set from more than 100,000 critically ill patients; to develop capabilities to acquire, standardize, tokenize, store, visualize, and label data such as structured electronic health record data, tokenized unstructured electronic health record data, telemetry and EEG waveforms, imaging, and social determinants of health; and to standardize data to the OMOP Common Data Model and transform data using approaches that limit re-identification.

Mechanism Details
Retrospective data collection (September 2025 webinar).
Data contributing sites create and curate a CHoRUS-specific clinical data extract and contribute it following the step-by-step process for extracting and contributing clinical data to CHoRUS in the Chorus_SOP workflow. The CHoRUS GitHub organization (overview captured 2025-11-14) provides standard operating protocols (SOPs) instructing data contributing sites about best practices for curating and delivering interoperable datasets, and lists a repository with tools to create and upload a CHoRUS Data Extract.
  • Preprocessing Details
    Semantic mapping and validation take place within CHoRUS, with clinical expertise contributing to them: the GitHub organization overview (captured 2025-11-14) states that its repositories provide validated semantic mappings for connecting clinical data in various source formats to international standards, that a chorus-mapping repository holds documentation and pooled tabular mappings along with an associated clinical validation SOP, and refers to downstream analytics on the mapped and assembled dataset.
Deidentification Details
Imaging: 1000 images are currently available, with de-identification in process for a larger cohort (September 2025 webinar).
Access Review Process
Access is controlled (September 2025 webinar). For trainees of the AIM-AHEAD Bridge2AI for Clinical Care Training Program, the webinar describes registration through a form collecting name, email, and institution; an email is sent once access is granted and compute is provisioned; and gaining access to the dataset requires a ".edu" email address, a requirement the webinar says is not a barrier to acceptance into the program, with program administrators assisting with this access if needed. The GitHub organization overview (captured 2025-11-14) lists contacts for requesting access: dbold@emory.edu or jared.houghtaling@tuftsmedicine.org.
