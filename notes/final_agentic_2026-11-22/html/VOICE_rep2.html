Motivation

For what purpose was the dataset created?

DescriptionName
The Bridge2AI-Voice consortium aims to generate a large-scale, ethically sourced voice, speech, and cough database linked to health metadata to support AI-driven research, with the goal of establishing an ethically sourced, diverse, and publicly available voice database linked to multimodal health biomarkers.
Ethically sourced voice database for AI research
A 2024 viewpoint by Voice project leaders states that the team's primary deliverable is to build a publicly available database of 30,000 human voices. This is a stated project goal, not the size of the current release.
Publicly available database of 30,000 voices (stated deliverable)
Specific Aim 1 of the funded project (and the primary objective of the IRB protocol) is to build a multi-modal, multi-institutional, large scale, diverse, and ethically sourced human voice database linked to other biomarkers of health that is AI/ML friendly, to fuel voice AI research.
Data acquisition aim
Per the healthsheet, the dataset aims to bridge the gap in large, diverse, well-documented voice data by providing an ethically sourced, large, and diverse dataset to develop, benchmark, or validate clinically applicable AI/ML models.
Develop, benchmark, or validate clinical AI/ML models

The adult Bridge2AI-Voice dataset of the Voice project is a large, ethically sourced, and demographically diverse voice dataset linked to health information, released by the NIH Bridge2AI initiative. Its current PhysioNet release, version 3.1.0 (published May 1, 2026), contains data for 833 participants across five sites in North America; the project healthsheet names the USA and Canada as the countries of collection. The release contains data considered low risk, including derived audio features such as spectrograms but not the original voice recordings, together with detailed demographic, clinical, and validated questionnaire data. Release 3.1.0 adds files related to audio quality metrics and per-audio metadata and updates validated diagnosis information across conditions with back-filled information.
Referent: the adult Bridge2AI-Voice dataset on PhysioNet, identified by its project-level DOI ("DOI (latest version)") 10.13026/37yb-1t42; the current release is 3.1.0 (version DOI 10.13026/8xbn-nq66). The Bridge2AI-Voice Pediatric Dataset is documented in the same bundle but is a separate PhysioNet project; none of its facts are used here, and no related_datasets entry is recorded because no passage states a typed relation between the two datasets (the adult and pediatric pages only note that the other dataset is also available on PhysioNet). Access terminology differs across sources: the 3.1.0 and 3.0.0 PhysioNet pages state "Credentialed Access" and that only credentialed users who sign the DUA can access the files, the 1.1 page stated that only registered users who sign the DUA could access the files, and the project documentation describes the featurized data as available under "registered access"; the PhysioNet 3.1.0 page (tier 1 in the source manifest) is preferred. Much of the project documentation's healthsheet was written for version 2.0.0, when the dataset was distributed through Health Data Nexus; statements taken from it are attributed to the healthsheet and are not presented as facts specific to release 3.1.0. Grant numbers appear in several forms: core project number OT2OD032720 (NIH RePORTER and the healthsheet), project number 3OT2OD032720-01S1 (PhysioNet acknowledgement), and RePORTER project number 3OT2OD032720-01S3 for fiscal year 2025. Language is not recorded as a slot value: the healthsheet states that English was used for communication with study participants and that the only language option for v2.0.0 was English, the IRB protocol was later amended to include Spanish-language data collection, and the 3.1.0 page states no language for the current release.

Method
Only derived audio features are released and all raw voice data was removed; raw audio transcripts were reviewed and recordings containing potentially identifying information or external voices were removed; spectrograms and similar features were excluded where the audio contained free speech, while static features that do not encode the sensitive information were retained; certain sensitive fields identified by a team of ethicists were removed.
Identifiers Removed
HIPAA Safe Harbor identifiers were removed. All direct identifiers (such as name, civic address, and social security numbers) were removed. State and province were removed; country of data collection was retained.
Deidentification Details
Identifiable information (under HIPAA and the Common Rule), as well as data considered sensitive, have been removed from this dataset. All spectrograms, MFCCs, Mel spectrograms, transcriptions, EMAs, and PPGs from open-response prompts are removed from the feature-only dataset.

Feature extraction for de-identification and data processing code
Data were exported and converted from REDCap using an open source library developed by the team; the code used to process the raw audio into the released features and to merge the source data into the phenotype files is open source in the b2aiprep library, and release 3.1.0 was generated with b2aiprep v3.0.0.

The feature-only dataset provides AI-ready derivations from the raw audio.
AI-ready derived features
OpenSMILE eGeMAPS features per audio file; Parselmouth/Praat speech features; torchaudio pitch contour, spectrograms, Mel spectrograms, and 60 MFCCs; Speech Articulatory Coding (sparc) features including electromagnetic articulography (EMA) estimates plus loudness, periodicity, and pitch; and phonetic posteriorgrams (PPGs) at 100Hz from the ppgs package.
Raw audio was preprocessed by converting to monaural and resampling to 16 kHz with a Butterworth anti-aliasing filter applied.
Audio standardization
Spectrograms were computed using the short-time Fast Fourier Transform with a 25ms window size, 10ms hop length, and a 400-point FFT.

Description
The public data releases do not contain an equal distribution of the disease categories.
Distinct iPad devices were used at each site, and the data were recorded with a head-mounted headset microphone that could be at slightly different distances.
Participants were screened for different disorders based on site, so they also had their data collected with different devices.
Confounding factors that might be present include noise artifacts, variations in diagnostic practices, inaccurate questionnaire responses, and underreporting.
