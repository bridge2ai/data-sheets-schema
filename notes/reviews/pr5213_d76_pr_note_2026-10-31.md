# #5213: preserve registered input identities under D76

Registered runs launched at the corpus root must retain their registered absolute
bundle, source-manifest and chunk-manifest paths. Previously, the relative-path
writer changed those spellings: shared-generation v2 failed during completed
capture after all provider-shaped calls, native execution permissions rejected
the source path, and shared-generation v1 rendered different instruction hashes
from different launch directories. The spec and provenance writer now share one
registration-binding predicate. Registration and completed-capture guards remain
strict; no prompt, canonical hash registry or historical run record is rewritten.

The exemption covers shared-generation v1/v2, native source attribution and its
execution/neutral-supervisor registrations, and explicitly bound older matched
and direct-arm registration builders. Receipt-completion v2/v3 inherit the shared
registration's input authority. Standalone receipt-completion v1 pins policy and
budget rather than input paths, so it does not select this exemption. Registered
evaluation uses its captured registration directly, and existing saved render-spec
replays retain their literal spellings.

Unregistered CLI runs retain #5213's cwd-dependent spelling: absolute inputs owned
by the launch root may become relative, while inputs launched elsewhere remain
absolute. This can change their instruction SHA and does not promise portable
resume. The recorder's cross-directory recovery tries bounded input spellings
only when the complete instruction SHA agrees; it neither guesses replacement
files nor changes recorded input hashes. Arm comparison rejects parent traversal
before lexical normalization so a symlink-parent path cannot select a matching
decoy or invent a historical Git name.

The additional legacy binding is an explicit boolean, serialized only when
selected. Changed registration-builder sources require exact authority re-pins
against their committed bytes. Existing historical registrations are not migrated
or weakened: strict identity checks may require new registration after code changes.

Round two also refuses post-construction changes to a registered bundle, manifest
or chunk-manifest spelling before public planning or execution can count tokens,
create requests or write run state. The guard compares the original literal
substitutions; it never rewrites them or refreshes a cached instruction. Literal
historical replay remains non-executable. Registration binding now classifies
every nonzero integer shared/native version, with shared generation still requiring
a registration. A classification test enumerates every RunSpec version/registration
field, including the non-input-pinning standalone receipt-v1 exception. Inverting
the default so only unregistered CLI constructors opt into relative rewriting is
a follow-up; this packet does not implement that broader policy change.

Existing historical-renderer and native-offline execution refusals retain their
precedence before accessing newer binding fields. Executable specs must still pass
the spelling guard before authority checks, output locks or any provider access.

Recorder recovery now tries known-owner lexical counterparts for bundle, manifest
and explicit or discovered chunk paths in both cwd directions. The manifest header
follows each candidate, and whole output maps change together. Each alternative
still requires the complete instruction SHA; byte-identical files at other paths
are refused.
