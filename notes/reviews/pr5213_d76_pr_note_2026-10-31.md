# #5213: preserve registered input identities under D76

Registered runs launched at the corpus root must retain their registered absolute
bundle, source-manifest and chunk-manifest paths. Previously, the relative-path
writer changed those spellings: shared-generation v2 failed during completed
capture after all provider-shaped calls, native execution permissions rejected
the source path, and shared-generation v1 rendered different instruction hashes
from different launch directories. The spec and provenance writer now share one
registration-binding predicate. Registration and completed-capture guards remain
strict; no prompt, canonical hash registry or historical run record is rewritten.

The exemption covers shared-generation v1/v2, native source attribution and its
execution/neutral-supervisor registrations, and explicitly bound older matched
and direct-arm registration builders. Receipt-completion v2/v3 inherit the shared
registration's input authority. Standalone receipt-completion v1 pins policy and
budget rather than input paths, so it does not select this exemption. Registered
evaluation uses its captured registration directly, and existing saved render-spec
replays retain their literal spellings.

Unregistered CLI runs retain #5213's cwd-dependent spelling: absolute inputs owned
by the launch root may become relative, while inputs launched elsewhere remain
absolute. This can change their instruction SHA and does not promise portable
resume. The recorder's cross-directory recovery tries bounded input spellings
only when the complete instruction SHA agrees; it neither guesses replacement
files nor changes recorded input hashes. Arm comparison rejects parent traversal
before lexical normalization so a symlink-parent path cannot select a matching
decoy or invent a historical Git name.

The additional legacy binding is an explicit boolean, serialized only when
selected. Changed registration-builder sources require exact authority re-pins
against their committed bytes. Existing historical registrations are not migrated
or weakened: strict identity checks may require new registration after code changes.

Round two also refuses post-construction changes to a registered bundle, manifest
or chunk-manifest spelling before public planning or execution can count tokens,
create requests or write run state. The guard compares the original literal
substitutions; it never rewrites them or refreshes a cached instruction. Literal
historical replay remains non-executable. Registration binding now classifies
every nonzero integer shared/native version, with shared generation still requiring
a registration. A classification test enumerates every RunSpec version/registration
field, including the non-input-pinning standalone receipt-v1 exception. Round
three closes that test over every dataclass field, each classified with a reason;
a new field must receive an explicit classification regardless of its name. Inverting
the default so only unregistered CLI constructors opt into relative rewriting is
a follow-up; this packet does not implement that broader policy change.

Existing historical-renderer and native-offline execution refusals retain their
precedence before accessing newer binding fields. Executable specs must still pass
the spelling guard before authority checks, output locks or any provider access.

Round three anchors supplied recorder inputs to the recording cwd before deriving
known-owner counterparts. Every admitted render candidate must agree with the
selected file's resolved address and lstat identity; the complete instruction SHA
is also required. This preserves both valid cwd directions while refusing a second
file at the same relative spelling. Traversal and symlink spellings remain literal.

Instruction reconstruction and consumed-byte evidence are distinct. A relative
instruction can reproduce in another corpus with the same layout. The CLI records
such input hashes as caller-asserted and describes the consumed-byte gap under
`unverified`. Only an admitting instruction that binds the absolute input spelling
qualifies for the existing verified basis in this recorder route. API usage ledgers
persist input identities, and API progress records carry them until successful
completion removes progress; native launch records also contain launch pins. This
recorder does not consult those files or treat freshly reconstructed identity,
source manifests or chunk metadata as independent run evidence. Existing internal
API callers retain their own explicit verified-input contract.

Round three retains construction bindings outside the mutable spec attributes and
uses the same input-integrity helper at every RunSpec entry, including batch and
prompt rendering before authority checks or output writes. It checks exact path
types, filesystem spellings, the complete binding roster and parsed shared
registration paths. Ordinary mutation cannot disable a spec's captured registered
status, and a fresh object cannot bypass rendering checks by changing its replay
flag. Fresh versus historical construction origin is retained independently too;
missing origin never implies replay. Shallow and deep copies retain the original
binding without recapturing mutated inputs. Successful direct replay construction
and the literal replay factory establish inspection-only origin, including the
completed SG2 subclass that deliberately skips live initialization. Unknown
restoration (including a pickle containing only spec attributes) fails closed;
recorded substitutions can be restored explicitly through `from_render_spec`.
Genuine reconstructed replay remains literal. `dataclasses.replace`
constructs and validates a new spec. This is an API
invariant, not protection against arbitrary hostile Python able to replace module
code or its registry. Historical refusal precedence remains intact; in the #5212
integration, the input check belongs after D68 legacy refusal and before D69's
ownership inventory, never inside `assert_current`.

The three SG2 publication/replay cases retain their original assertions but run
in individual subprocesses with a 1,800-second deadline. The supervisor owns
their process group and cascades an enclosing test deadline before reaping the
leader. Completed child runs retain source, import and complete phase evidence;
timeout and interrupted runs remain failures. External SIGKILL-only cancellation
is not covered by that cleanup claim. Diagnostic observations and scheduling
estimates are recorded separately from final acceptance, without claiming a
cache leak from slow runtime alone.
