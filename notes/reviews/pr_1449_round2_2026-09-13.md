# PR #1449 — review round 2, 2026-09-13

The first independent Codex plugin review covered
`f76eff2d9982e903576125d3203beb3f99bcc7c4` against the generation dependency.
Its four findings are filed as #1450–#1453.

* #1450: the new semantic-output acceptance command requires version 2.0.
  Changing a result to version 1 cannot bypass the original-input and agent
  definition checks. Historical classification still recognizes old versions.
* #1451: both rubric10 agents now use the same source-aligned item fields and
  quality thresholds. Their semantic checks remain a distinct instrument.
  Source-name/field coverage and actual schema path resolution are checked
  for all fifty items in both definitions, rather than names alone.
* #1452: full/Core distribution formats keep their grouping and equivalent
  format/MIME labels count as one type. A distribution's size alone is not
  format evidence.
* #1453: semantic rubric20's general scoring instructions offer only its
  accepted 0/3/5 numeric bands. Other instruments retain their own scales.

The source-scope audit compared all fifty item names, source fields, actual
schema paths and criteria. These representation differences retain the source
concept rather than inventing a top-level slot:

| Source concept | Reachable representation / scope guard |
|---|---|
| E1.1 RRID | A persistent identifier in `id`. |
| E1.5 hierarchy | `parent_datasets` or typed `related_datasets`; affiliation is not a dataset relationship. |
| E2.2 regulatory leaves | Nested regulatory restrictions and current `data_governance.committee_contact`; equivalent jurisdictional frameworks count. |
| E2.4/E3.2 format, MIME, encoding | Dataset-owned distribution and file fields; format plus its MIME alias is one type. |
| E3.5 reuse guidance | Intended, prohibited and discouraged uses; a repository URL is not use guidance. |
| E4.1 review | Ethics review/waiver, oversight decision or DPIA; a committee contact alone is insufficient. |
| E4.3 privacy risk | `participant_privacy.reidentification_risk`. |
| E4.5 vulnerable populations | `at_risk_populations` and compensation. |
| E5.1–E5.3 subset flags | Flags describe subset roles; alone they do not describe cohort characteristics or counts. |
| E6.5 release notes | Release/derivation detail in `updates.update_details`, inherited `description` or `notes`; generic notes or an update schedule alone are insufficient. |
| E7.3/E7.4 funding | Any named funder and its own award conventions; no US agency is required. |
| E8.2 acquisition | Source descriptions may name acquisition methods; a source name or URL alone is insufficient. |
| E8.3 processing | Imputation is a processing strategy; applicability remains independent of released software. |
| E8.4 tooling | Reachable `used_software` and named-tool evidence in processing properties; retain the released-data transformation threshold and role exclusions. |
