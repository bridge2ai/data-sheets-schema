## Finding: the public omission checker now accepts an unsent request identity

`src/data_sheets_schema/audit_omissions.py:348–350`, introduced in `0ca2f78d7`,
unconditionally accepts either the original prepared request's SHA-256 or the hash
of a payload with `trim_omission_schema` applied. The public API has no shared
generation selector at this point. Passing the exact original `saved_request` does
not remove this alternative acceptance.

The independent test in `tests/test_wave4_a14_review.py` prepares a real omission
request using the released API, supplies that request to `saved_request`, and uses
the real response parser/checker. The control response echoes the prepared hash and
passes. The challenge response changes only `request_sha256` to the distinct hash
of the trimmed schema projection, which was never the saved request. The checker
still returns `protocol_complete: true`: **one control passed, one regression test
failed**, with no mocks of the checker or identity calculation.

The selected runtime also feeds omission responses through this same checker via
`typed_audit.index`. It now sends the trimmed wire hash and includes the original
packet hash separately (`typed_audit_runtime.py:145–155`), but accepts either at
the inner response check. That additional consequence is established by call-path
inspection here; the new causal test specifically exercises the public API.

**Required repair:** retain strict request-hash validation for the public/legacy
API. Give the selected shared route an explicitly captured, deterministic wire
projection identity, validated against its actual selected contract. Do not accept
an arbitrary caller-provided alternative hash, silently infer selected mode from a
response, or normalize saved historical records. At minimum verify:

- unchanged legacy responses still pass;
- a public response naming an unsent projection fails with `request_identity`;
- a selected response naming the actual projected wire request passes;
- the selected route rejects a response echoing the old packet hash instead;
- live, resumed and completed selected checks use the same captured identity.

The root/lead must review that implementation before any protected-file hook is
changed. This report supplies the failing test and a bounded design requirement,
not an unreviewed production patch.
