## Independent round-3 findings


Target: branch diff against ef13c5a3f0907953a94d68cec0cdc5889f4ffec0
Verdict: needs-attention

Do not ship yet. Synthetic probes reproduced false provenance, changing receipt verdicts, and incomplete external-dataset routing and validation. PR 1396 remains a separate merge prerequisite.

Findings:
- [high] [P1] Bind resumed phases to their manifest inputs (src/data_sheets_schema/api_runner.py:4823-4827)
  Resume identity includes only project, label, method, and condition. After completing full/core with manifest A, resuming with source/chunk manifests B skips those phases and continues with their old outputs. A synthetic _execute probe reached audit with exactly this mixture. The final record then attests B as the input, misrepresenting what produced the retained phases.
  Recommendation: Persist source and chunk manifest identities before generation; reject drift before resuming, or reuse immutable copies of the original inputs.
- [high] [P1] Preserve the selected manifest in agentic recording (src/data_sheets_schema/cli/provenance.py:365-367)
  Rendering generic_v9 with an external bundle and --manifest M produces a header naming M, but its emitted provenance-record command omits --manifest. Following that command ignores the header's explicit path and selects AUTO against the study registry. The synthetic probe passed manifest=None to build_record, falsely recording that no source manifest was selected.
  Recommendation: Include the selected manifest, including explicit none, in the rendered recording command and preserve that selection when reconstructing provenance.
- [medium] [P2] Verify chunk identity after replay reconstruction (src/data_sheets_schema/receipts.py:1376-1381)
  After a manifest digest mismatch, reconstruction checks only rule and chunk count. An explicit two-chunk manifest with exchanged IDs passes chunk_marked_bundle. Recording its digest and then replacing its sidecar with canonical chunking changed the same receipt from zero verified snippets plus an adjacent-chunk finding to one verified snippet and no findings. Replay therefore credits a different chunk identity.
  Recommendation: Validate canonical chunk mappings before generation and verify reconstructed identity, or retain and replay the exact selected manifest.
- [medium] [P2] Honor the declared bundle destination during concatenation (src/data_sheets_schema/cli/download.py:159-160)
  For a mapping declaring bundle: /review/bundles/cohort.txt, concatenation without --output-file still writes the conventional EXT_preprocessed.txt path. Chunking and API planning subsequently resolve the declared path instead. The synthetic probe confirmed the conflicting destinations. This either breaks the pipeline or leaves generation consuming an older bundle already at the declared location; Make also forces the conventional destination.
  Recommendation: Default concatenation to Registry.bundle(project), and stop Make from overriding declared destinations unless explicitly requested.
- [medium] [P2] Reject invalid context declarations before assembling requests (src/data_sheets_schema/registry.py:254-259)
  Explicit-manifest validation checks only that YAML loads as a mapping. A source declaring priority: first passes RunSpec construction; ranked() raises during integer conversion, and source_ranking_block silently returns None. The synthetic build_phase probe successfully assembled a request without the declared ranking, while bookkeeping described it as absent or unreadable. Paid generation can proceed under silently discarded conflict-resolution rules.
  Recommendation: Validate selected context declarations before planning or execution, and propagate invalid ranking errors instead of treating them as missing optional context.
- [medium] [P2] Use the selected registry for canonical-record gaps (src/data_sheets_schema/cli/runs.py:463-470)
  The canonical status route still computes missing projects from constants.PROJECTS. With a registry containing only EXTERNAL and no canonical records, --missing lists the five study projects. Adding --project EXTERNAL instead exits successfully with 'Every project has a canonical record.' Both outcomes were reproduced, so the new root manifest option can produce a false completeness report.
  Recommendation: Compute and filter canonical-record gaps using the selected registry, including an explicitly requested external project.
