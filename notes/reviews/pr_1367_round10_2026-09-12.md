# PR #1367 continuation — round 10 — 2026-09-12

Independent round-9 review of `93a9d4257ba02f52601d4369eebc4db67299157f`
confirmed the preceding fixes and found one remaining fresh-restart defect,
filed as #1430. An interrupted generation can leave a valid snapshot index
without final provenance. If its usage journal is subsequently missing or
malformed, a fresh run archived that index without recording its generation
as a predecessor. The next pre-call accounting check then refused the archive.

A fresh run now reads the current snapshot index's own validated identity
independently of the damaged usage journal. It records that one matching run
generation in the new journal before snapshot activation. Unrelated archived
generations are never adopted. This ordering also survives an interruption
before the replacement snapshot index is written.

The defect reproduced with both missing and malformed journals before the
fix. All 33 focused tests and 74 broader recovery tests pass. New behavioral
coverage verifies retained predecessor bytes, successful completed resume
without provider calls, durable predecessor identity across activation
failure, and refusal of unrelated unaccounted archives. Tests use fake
providers and make no production generation or evaluation requests.

Round-8 full CI passed 3,884 tests with four skips. Round-9 CI was still
running when this patch was prepared. Full CI and independent Codex plugin
review of the committed round-10 head remain required before merge.
