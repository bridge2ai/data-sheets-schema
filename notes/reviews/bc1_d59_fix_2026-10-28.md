# BC1 D59 implementation and offline fit — 2026-10-28

D59 is implemented for the common BC1 path: one full catalog, no per-slot `domain_of`, one bundle, and v10 A14 downstream. D60 is preserved: no typed-stage cache breakpoint. **The conservative F5/F7 gate still refuses the CHORUS plan at its existing limits.** The smaller requests do not make every possible bounded future carry fit; raising only the aggregate cannot fix an oversized call.

This is offline implementation and sizing, not an A21 launch or a matrix decision. The $60 A21 owner decision is recorded here as context; no decision record or campaign budget was changed.

## Change and calibration

- The model-facing projection verifies the duplicate catalog against the captured catalog, replaces it with a SHA-256 reference, and references the codec dictionary chunks instead of repeating the bundle. Full host requests and response identities remain available to validators. Both full and core catalogs retain their definitions apart from the redundant inverse `domain_of` index.
- `api_runner.build_phase` and `bc1_runtime.require_request` use the existing A14 implementation for full, receipt completion, reconcile, report and regate. The receipt continuation inherits its full request.
- The registration’s BC1 contract explicitly records the calibration and source. Worker/omission use **2.48 bytes/token**. Integration uses **1.75**, rounding down the measured minimum 1.755 (reported as 1.76) to avoid rounding toward underestimation. The requested sensitivity columns use 2.48 and 2.77 for every call. These are extrapolations from saved usage, not measured BC1 token counts. The historical non-BC1 2.0 constant remains unchanged for byte parity.
- F5 recomputes estimates from wire bytes, rejects inconsistent fit flags, enforces each per-call room and aggregate for every scenario, and runs before registration outputs are written.
- F7 replaces the 86-byte receipt placeholder with `bc1_audit_carry` of the pinned saved receipt-completion result. A missing or mismatched result refuses sizing. Use the original intermediate directory containing `PROJECT_receipt_completion_result.json`, or supply `SizingRecord.receipt_result` in Python.
- F7 retains the ASCII scenario for comparison and adds an escaped-byte bound. Valid JSON text can occupy four wire bytes per input byte after two string encodings. Backslash filler reaches that bound; it is explicitly **not a valid model response or token-density calibration**. No output cap is lowered, and no source material is truncated to force fit.
