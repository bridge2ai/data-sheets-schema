### D76-R3-H1 — timeout supervisor can leave an ignoring descendant alive

Independent read-only helper review found that the proposed round-three timeout
runner sent group SIGTERM and then reaped the pytest controller immediately when
it exited. A worker or grandchild ignoring TERM could remain alive while final
source snapshots and terminal evidence were written. This is a helper finding,
discovered before using the new runner, not an observed production failure.
Retain ownership of the unreaped leader until group cleanup is finished, then
reap; test an ignoring descendant and preserve timeout/partial evidence without
calling it completed acceptance. AGY should file this local finding with the
packet's review issues. Existing round-two baseline evidence is unchanged.

### D76-R3-G1 — changing the replay flag can bypass rendering input checks

Independent read-only review of the proposed binding repair found that the
guard returned on the current `_replay_only` flag before consulting its retained
construction binding. Changing that flag on a fresh registered object could let
planning or prompt rendering bypass the integrity check. Execution still refuses
replay unconditionally; this finding does not demonstrate provider access.
Distinguish genuine reconstructed replay (no fresh construction binding) from
mutation of a freshly bound object, and refuse the latter before authority or
output. Preserve historical execution refusal order. Add separate frozen
regressions and run them at 0fa before validating the repair; AGY files the issue.

The original six-case G1 fixture omitted API headers needed by literal replay.
Five cases therefore reached a missing-header refusal rather than demonstrating
the suspected bypass. Their original evidence is retained. The corrected fixture
binds headers while fresh, with all assertions unchanged: five cases then reach
authority, rendering or output, while unshared plan reaches a later chunk-name
refusal caused by the mutated alias. That last case proves a missing early
input-integrity refusal, not spend or an output write.

### D76-R3-T1 — the first SG2 wrapper deadline did not own descendants

Independent read-only review of the proposed test wrapper found that
`subprocess.run(timeout=...)` kills and reaps its direct child without owning or
retiring the child's process group. A descendant could outlive the failed node.
Use the reviewed bounded group supervisor, retain the leader until cleanup and
save timeout evidence. This was caught before the wrapper was executed; the
unchanged baseline diagnostic remains separate. Local issue for AGY.

The follow-up review identified the nested case too: an outer pytest deadline
can terminate the waiting worker while the SG2 child owns another session. Its
timer must not disappear with that worker. Exercise the actual nested timeout
and verify descendant retirement before terminal evidence; a separately
sessioned-child disclaimer alone does not satisfy this wrapper's cleanup rule.

The second read-only pass found that subclassing `KeyboardInterrupt` allowed
CPython's `Popen.wait` to reap the leader before the cleanup handler ran. Use a
distinct `BaseException` and install its deferred TERM handler before launch,
closing the startup window as well. The focused contracts cover both ownership
failures. External SIGKILL-only interruption and an already-reaped group remain
explicitly unproved; no successful retirement is inferred from an exit code.

### D76-R3-T2 — SG2 child source and environment isolation was incomplete

that those bytes matched its reported commit. Require exact tracked source and

outer observer or reuse its evidence namespace. Preserve all original SG2 body
assertions and require actual setup/call/teardown outcomes, rather than trusting
the child exit code. Local issue for AGY, found before wrapper execution.

### D76-R3-T3 — scheduling provenance could be incomplete after a write failure

### D76-R3-H4 — notes runner contradicted the pinned transport cache contract

The new binding field changes a newly built legacy render spec, while older saved

### D76-REG-2 — legacy chunk discovery supplies a relative registration locator

The direct and matched registration preparers may discover a relative chunk path

### D76-REG-3 — binding an already-relative spec can still reach late refusal

header, instruction and capture are established. Supplied absolute spellings
remain unchanged, parent traversal is not collapsed, and literal historical
replay remains untouched. No registration or permission check is weakened.

binding remains backward-compatible for saved replay. Any changed authority source
must be re-pinned by exact bytes and a truthful committed source snapshot; no
verification guard is relaxed. Historical run evidence stays unchanged.
