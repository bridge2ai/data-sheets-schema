## Additional independent review findings from this repair

These are issue-ready records, including findings fixed before publication.

### D76-CLI-2 — recorder input alternatives omit frozen output spellings

Independent source review during final validation confirms another axis of the
cross-directory instruction: a nested agentic render freezes absolute output
paths, while a fresh root recorder freezes relative outputs. Trying only input
spellings cannot reproduce the complete instruction SHA. Preserve the original
candidate first, then admit at most one whole-output-map lexical counterpart
under the known corpus owner. Unknown, mixed, foreign or parent-traversal maps
get no invented alternative. The full instruction SHA remains the only admission
gate; registered render-spec selection remains separate. Existing four root
recorder scenarios exercise the regression. The terminal c02a light run confirms
all four root cases fail: explicit dates refuse the instruction, while recovered
dates retain a mismatch. The same-cwd controls pass. Repairs require a fresh
detached-head run; c02a evidence is retained unchanged.

### D76-TEST-1 — native relative-input regression has an incomplete manifest

The new native binding regression reuses a generic renderer-8 fixture without
the `processed_file` metadata required by renderer 16. Its instruction roundtrip
therefore cannot exercise the intended native behavior. Add that field only to
this test's synthetic native manifest, retaining its input identities, all
assertions and the production metadata guard. Do not change the generic fixture
or the independent reviewers' probe files. The terminal trace confirms all path
and render-spec assertions passed before the missing-field error at instruction
rendering. The original c02a run is retained: 2,676 passed, 5 failed and 2 skipped,
with complete accounting and no offline denials; outcome SHA-256
`b26ca3fdad48989e8e300f7755662a602a13ad7ee6dfa96dbb42fab955c89bf5`.

Future execution logs use verbose node identities so long final cases cannot hide
earlier failure identities. Collection keeps `-q`; test selection, scheduler,
source checks, offline guards and phase acceptance are unchanged.

### D76-CLI-1 — discovered chunk spelling omitted by the new recorder alternative

The first repair overwrote `chunk_manifest` with null when the user omitted the

was safe but the requested recovery was incomplete. Preserve the discovered
locator and try at most its one known-owner lexical counterpart, with no file
search and the full SHA gate unchanged. Tests now include explicit and discovered
chunks, root and nested recording, and explicit versus recovered dates.

### D76-H1 — caught offline guard denials could be omitted from acceptance

prevent acceptance. Preserve original baseline helper hashes and evidence.

### D76-REG-1 — legacy registered jobs need explicit compatibility treatment

The new binding field changes a newly built legacy render spec, while older saved
jobs omit it. Rebuilding an old job under current code must not silently replace
its captured specification. The disposition is strict refusal by existing
source/spec identity gates and fresh registration for the new code. Literal
saved-spec replay remains unchanged. D76 explicitly places this repair before the
next registration; it does not authorize migrating historical registrations.

### D76-REG-2 — legacy chunk discovery supplies a relative registration locator

The direct and matched registration preparers may discover a relative chunk path
when run at the checkout root. Merely exempting RunSpec's rewrite preserves that
relative locator, conflicting with the registered absolute-input contract. The
builders must supply absolute bundle, manifest and chunk locators and put those
same spellings in their job pins. The direct-preparation regression checks all
three fields against the resulting registration, not only RunSpec's bundle.

### D76-REG-3 — binding an already-relative spec can still reach late refusal

Skipping the new relative rewrite is insufficient when a Python caller binds a
registration to a spec that was already relative, or discovers a relative chunk
locator after selection. Shared-generation capture compares absolute locators,
so this case can pass early checks and fail the later literal-display gate.
Fresh bound specs must freeze relative locators after discovery, before their
header, instruction and capture are established. Supplied absolute spellings
remain unchanged, parent traversal is not collapsed, and literal historical
replay remains untouched. No registration or permission check is weakened.

Three live legacy fresh-spec constructors lack the modern shared-generation/native
attribution selection fields. They cannot be identified safely by profile-basis
prose. An explicit boolean registration binding covers these callers, while absent
binding remains backward-compatible for saved replay. Any changed authority source
must be re-pinned by exact bytes and a truthful committed source snapshot; no
verification guard is relaxed. Historical run evidence stays unchanged.
